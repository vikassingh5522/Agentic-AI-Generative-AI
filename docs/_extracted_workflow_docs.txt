OpenLayer Workflow 21
Cheque Book Request & Issuance
Enterprise Workflow Blueprint Version 2.0
Workflow Objective
Provide an end-to-end digital workflow for cheque book requests from multiple banking channels with secure authentication, automated validations, AI-assisted fraud detection, configurable approvals, secure printing, dispatch, customer communication, and immutable auditability.

Part 2 — Generic Test Run + Compact Process Cards
Overview: Shrink the process carousel cards and generalize AI Runtime Test Run / Execution Progress so every workflow and process (existing and newly created) uses the same canvas monitor path—not only Cheque Book.
2.1 Problem Statement
Bottom process cards still look large with extra whitespace/chevrons.
Backend monitor path is imported from Cheque Book only (execution_engine.py → workflows.banking.cheque_book.canvas_runner), and templates hardcode WF-CHEQUE-BOOK. New/other workflows do not get the same empty-canvas fallback or seed behavior.
Process cards always show static Ready — they do not reflect Test Run red/green/yellow status.
Default for empty canvases: use a generic Start → AI Agent → API/Connector → End template for any workflow (same as Cheque Book linear; P07-style gateway stays Cheque Book-specific only when process name/code matches P07).
Architecture Flow
Designer (any workflowId) → POST /ai_runtime/execute → ExecutionEngine → Resolve mapped or GenericAgent + Generic ProcessCanvasRunner → Trace (steps / node / edge statuses) → Execution Progress + process cards
